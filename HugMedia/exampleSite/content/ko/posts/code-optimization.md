# 코드 최적화 시연과 읽는 시간

이 페이지는**코드 블록(구문 하이라이트 + 언어 라벨 + 복사 버튼)**과**읽는 시간/단어 수 카운트**와 관련된 긴 본문을 시연합니다.'최적화 전후' 비교라는 흔한 작성법도 보여줍니다.

## 시나리오: 합계 최적화

단순한 Python 구현은 직관적이지만, 가독성과 경계 처리에는 개선의 여지가 있습니다.

**최적화 전(단순한 항목별 누적):**

```python
def sum_before(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total
```

**최적화 후(가우스 공식 O(1), 인자 검증 포함):**

```python
def sum_after(n: int) -> int:
    """1 + 2 + ... + n 을 O(1) 로 반환한다."""
    if n < 0:
        raise ValueError("n must be non-negative")
    return n * (n + 1) // 2
```

`O(1)`이나 함수명 `sum_after` 같은 인라인 코드도 등간격 글꼴로 표시됩니다.

## 설명

1. `sum_before`는 교육용 단순 버전입니다.
2. `sum_after`는 공식으로 직접 푸는**코드 최적화**의 대표 예시입니다.
3. 두 코드 모두 언어 라벨(python)과 우상단 복사 버튼이 있어야 합니다.

## 긴 본문(읽는 시간/단어 수 카운트 플레이스홀더)

같은 글에 단순 버전과 최적화 버전을 둘 다 두는 이유가 궁금할 수 있습니다. 사실 이는 엔지니어링 라이팅에서 매우 흔합니다. 먼저 '의미가 가장 명확한' 버전으로 독자가 의미를 이해하게 하고, 다음에 '성능이 가장 우수한' 버전을 실무에서 쓰게 합니다. 리더는 이를 바탕으로 단어 수와 예상 읽는 시간을 집계해 글 머리에 표시합니다. 본문이 충분히 길면, 소셜 스타일(예: 샤오홍슈, 즈후)의 카드 요약도 이를 바탕으로 유한 행으로 잘립니다.

이 문장은 제목, 목록, 표, 두 코드와 함께 읽는 시간/단어 수 카운트와 TOC 목차 생성을 테스트하는 다계층 페이지를 구성합니다. 3단계 제목을 늘릴 때마다 오른쪽(또는 상단) 목차에 앵커 항목이 늘어나고, 스크롤 시 해당 위치가 하이라이트됩니다.
