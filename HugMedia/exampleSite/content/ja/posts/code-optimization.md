# コード最適化の実演と読了時間

このページは**コードブロック（構文ハイライト＋言語ラベル＋コピーボタン）**と**読了時間／文字数カウント**に関する長い本文をデモします。「最適化の前後」の比較というよくある書き方も示します。

## シナリオ：合計の最適化

シンプルな Python 実装は直感的ですが、可読性と境界処理には改善の余地があります。

**最適化前（単純な逐次加算）：**

```python
def sum_before(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total
```

**最適化後（ガウスの公式 O(1)、引数検証付き）：**

```python
def sum_after(n: int) -> int:
    """1 + 2 + ... + n を O(1) で返す。"""
    if n < 0:
        raise ValueError("n must be non-negative")
    return n * (n + 1) // 2
```

`O(1)` や関数名 `sum_after` などのインラインコードも等幅フォントで表示されます。

## 説明

1. `sum_before` は教育用の素朴なバージョン。
2. `sum_after` は公式で直接解く、**コード最適化**の代表例。
3. どちらのコードにも言語ラベル（python）と右上のコピーボタンが必要です。

## 長めの本文（読了時間／文字数カウントのプレースホルダー）

同じ記事に素朴版と最適化版の両方を置く理由が気になるかもしれません。実はこれはエンジニアリングライティングで非常に一般的です。まず「意味が最も明快な」版で読者が意味を理解し、次に「性能が最も優れた」版で実務に使えるようにします。リーダーはこれに基づいて文字数と予測読了時間を集計し、記事の冒頭に表示します。本文が十分に長ければ、ソーシャルスタイル（例：小紅書、知乎）のカード概要もこれに基づいて有限行に切り詰められます。
