# 代码优化示范与阅读计时

本页用于演示**代码块（语法高亮 + 语言标签 + 复制按钮）**与**阅读时间/字数统计**相关的较长正文。它也演示了"优化前后"对比这一常见写法。

## 场景：求和优化

一段简单的 Python 实现非常直观，但可读性与边界处理可以更好。

**优化前（朴素逐项累加）：**

```python
def sum_before(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total
```

**优化后（高斯公式 O(1)，并做入参校验）：**

```python
def sum_after(n: int) -> int:
    """返回 1 + 2 + ... + n，O(1)。"""
    if n < 0:
        raise ValueError("n must be non-negative")
    return n * (n + 1) // 2
```

其中行内代码如 `O(1)`、函数名 `sum_after` 均会以等宽字体呈现。

## 说明

1. 前一段 `sum_before` 是教学用朴素版本；
2. 后一段 `sum_after` 用公式直接求解，属**代码优化**常见示范；
3. 两段代码都应有语言标签（python）与右上角复制按钮。

## 一段较长的正文（用于阅读计时/字数统计的占位）

你可能会好奇，为什么在同一篇文章里既保留朴素版又保留优化版。事实上，这在工程写作里非常常见：先给出"道理最直白"的版本让读者理解语义，再给出"性能最优"的版本让人在实践中使用。阅读器会据此统计字数与预计阅读时长，并在文章头部展示。若正文足够长，社交风格（如小红书、知乎）的卡片摘要也会据此截断到有限行数。
